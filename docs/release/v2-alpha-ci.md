The remaining Windows assertion failure rejected an ordinary completed artifact rewrite as `UNSAFE_SOURCE`, before reaching the expected `ATTACHMENT_CONFLICT`. On native Windows Python 3.12, path and descriptor stat calls returned different `ctime` values for the same file, while their birth times and device/inode/size/mtime matched. This agrees with the [CPython report](https://github.com/python/cpython/issues/157671) and [Python 3.12 timestamp documentation](https://docs.python.org/3.12/whatsnew/3.12.html).

The candidate passes **25 cases**, including the complete existing attachment suite. Removing only the descriptor change-clock check from an isolated in-memory copy causes the independent same-size/restored-mtime control to fail. The original failure remains retained.
