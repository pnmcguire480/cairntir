# 1.14.0: three new commands and the evaluator's finding fixed

Status: **PREPARED, NOT PUBLISHED — awaiting the maintainer's approval**. Prepared 2026-11-12.

## Decision

On 12 November 2026, after the fix for the evaluator's finding merged, the
maintainer asked for the next release to be prepared: "get the 1.13.1 proper and
ready. be sure that all documentation and proceduring is proper."

The number prepared here is 1.14.0, not 1.13.1. The
[release policy](../release-cadence.md) says a patch is "fixes without a new
capability" and a minor is "additive capability". `main` carries three new
commands since 1.13.0, so the policy gives this release a minor number. The
maintainer confirmed the number the same day: "1.14.0 is fine". Publication
still needs their explicit approval.

2.0.0 stays reserved for the finished roadmap.

## What an existing user must do

Nothing beyond upgrading. There is no database schema change and no change to
the embedding identity since 1.13.0, so a store that works with 1.13.0 needs no
reindex. A store still on 1.12 or earlier needs the one reindex described in the
[upgrade guide](../embedding-artifacts.md).

## Independent evaluation of 1.13.0

An independent evaluator on a second computer tested published 1.13.0 on
12 November 2026 and reported **FAIL on one Tier 2 finding**, with no Tier 1
finding and no data loss: an exact `cairntir replay` retry printed a chain link
that was never saved and called the reused prediction new. The stored data was
correct. That verdict stands for 1.13.0 as it was reported.

The builder reproduced the finding with a regression test that failed before the
fix and passes after it (#166).

The evaluator extracted 40 promises from the public documentation: 10 passed, 1
failed, and 29 were not tested at their full stated scope.
