## What BabyTIEROS was

BabyTIEROS was an AI-assisted development methodology and project scaffold,
not a semantic memory engine. Its central ideas were:

1. ten durable project documents as externalized context;
2. a five-tier model-routing and escalation system;
3. spec-before-code and explicit out-of-scope boundaries;
4. chunk-based decomposition with completion gates;
5. human approval for risky operations;
6. structured session handoffs;
7. human-only sniff tests that agents could not optimize against;
8. decision logs, debt trackers, performance contracts, and lessons learned.

The ten-document scaffold was:

- `CLAUDE.md` — identity, current state, rules, and session handoff
- `SPEC.md` — users, stories, priorities, acceptance criteria, and non-goals
- `SCENARIOS.md` — happy paths, failures, edge cases, and state changes
- `ARCHITECTURE.md` — boundaries, data model, integrations, security, debt,
  performance, and decisions
- `AGENTS.md` — tier routing, escalation, delegation, and approval checkpoints
- `CODEGUIDE.md` — implementation conventions
- `ART.md` — visual and interaction direction
- `CONTEXT.md` — why, stakeholders, constraints, and domain background
- `SNIFFTEST.md` — human-only smoke, adversarial, first-use, accessibility,
  mobile, performance, and regression tests
- `README.md` — public project overview

## What BrainStormer inherited

BrainStormer absorbed BabyTIEROS as its **Kernel**:

- first-time and returning initialization;
- the ten-file scaffold;
- stack and maturity detection;
- skill/model routing;
- chunk decomposition and handoffs;
- human checkpoints;
- architecture and decision records;
- quality gates;
- project-state restoration.

BrainStormer then expanded it with CodeGlass comprehension, ideation, design,
PALADIN quality, Crucible, agent species, an Obsidian vault, append-only TSV
ledgers, diff-derived rules, retrospectives, autosave, hooks, daemon profiles,
MCP, and a large agent catalog.

## What Cairntir inherited

Cairntir retained the purpose behind several BabyTIEROS mechanisms while
replacing their implementation:

- project documents as memory → verbatim drawers and four retrieval layers;
- `CLAUDE.md` Last Session → `session_start`, recall, and automatic capture;
- decision logs → prediction-bound drawers and supersession;
- assumption checking → Crucible;
- ship gates → Quality;
- lessons learned → belief mass, Reason outcomes, and agent memory;
- hot/warm context → identity, essential, on-demand, and deep layers;
- cross-project vault → wings and cross-wing recall;
- repeatable workflows → recipes.

## The lineage rule

Lineage is not a shopping list. Cairntir does not restore an old mechanism
merely because an ancestor had it.

For every ancestral capability:

1. recover the user outcome it protected;
2. determine whether the outcome still serves the North Star;
3. place it in the smallest correct layer:
   - **core invariant** for memory correctness and trust;
   - **recipe** for repeatable reasoning or governance;
   - **projection/integration** for human interfaces such as Obsidian;
   - **host responsibility** for agent orchestration;
4. reject the old mechanism if a simpler Cairntir-native mechanism provides
   the same outcome.

The detailed disposition is recorded in
`docs/lineage/evolution-audit-2026-07-27.md`.
