# Independent 1.12.0 release acceptance

This release packages the accepted automatic-backup capability from merged
commit `e27fe04a21eeb4db32fadb6804ee3afb7c617a58`. Independent tester:
`/root/foundation_tester`. The user authorized publication and installation.
Release metadata changes begin only after this acceptance generation is frozen.

The 58 non-version Python source files must remain byte-identical to the accepted
backup implementation. The version module may change only its `__version__`
literal from 1.11.0 to 1.12.0. The six original backup acceptance inputs and their
freeze manifest remain immutable; the accepted 29-case suite, 39 store tests and
three separate supporting probes supply behavioral coverage. No new runtime
feature, schema change, dependency addition or changed locked dependency is part
of this release. Historical version-specific results remain historical.

The standalone verifier `tests/release/verify_v1_12_0.py` checks source integrity,
aligned project/lock/plugin/module versions, unchanged dependency declarations
and locked non-Cairntir packages, a dated 1.12.0 changelog entry and empty
Unreleased section. It is deliberately not an automatically collected pytest:
a future release must create a new generation rather than edit this one.

Candidate packaging must contain all 74 Cairntir package files, including the
accepted source, typing marker, three bundled skills and every bundled recipe.
Wheel and source distribution bytes must match the checkout for these files;
distribution metadata must identify 1.12.0. Plugin metadata is verified in the
versioned repository/tag, since the plugin is not part of the package archive.

```powershell
.\.venv\Scripts\python.exe tests/release/verify_v1_12_0.py source
.\.venv\Scripts\python.exe tests/release/verify_v1_12_0.py package --wheel <candidate.whl> --sdist <candidate.tar.gz>
.\.venv\Scripts\python.exe -m pytest tests/acceptance/test_automatic_backups.py tests/unit/test_store.py tests/unit/test_backup_failure_boundaries.py --no-cov -q
```

The coordinator also runs the existing full regression/evaluation, static
analysis, documentation, public API, policy, commitment/seam, advisory and build
gates. The reviewed PR head must pass every required native OS/Python check;
the merged source tree must equal that head. The immutable `v1.12.0` tag must name
the verified merge. No gate may be bypassed because an earlier release passed.

After publication, independently download the workflow dist artifact, GitHub
Release assets and PyPI distributions and compare SHA-256 values. Both wheel
and sdist require cryptographically verified provenance, pinning repository,
`.github/workflows/release.yml@refs/tags/v1.12.0`, exact source/signer commit,
GitHub OIDC issuer, hosted runner and exact release run/attempt. All five release
jobs must succeed. ZIP container metadata differences from the local candidate
are acceptable only after every member byte and metadata difference is explained.

Install the public version into a fresh isolated environment. Verify all 74
installed package files against the public wheel and check declared dependencies.
Use a disposable store and cached models for redirected CLI version/help/recipes,
backup configure/run/status/disable, a verified independently restorable snapshot,
and actual separate stdio MCP processes. Both transports must report 1.12.0;
MCP still advertises 21 object-root schemas including checkpoint/resume. Preserve
cross-host exact Unicode resume, typed invalid-checkpoint handling and CLI/MCP
parity while an MCP client keeps the store open. No commercial model invocation
is represented as a passing test without such an invocation.

Before production installation, independently snapshot and hash all source
tables/schema objects, physical vectors, provenance/access/workflow state,
existing backup configuration and manual baseline files. After the package-only
upgrade, verify installed package/import/CLI/MCP versions and exact public-wheel
files, dependency compatibility and unchanged source application data. Schema
must stay at 7; no migration or reindex is authorized. Pause intentional memory
writes through this preservation window. Do not stop user applications; existing
MCP sessions need reconnecting and are not claimed reloaded from fresh probes.

Activate the already authorized machine destination through persisted owner
configuration, with interval 12 hours. Verify enabled status and a fresh managed
snapshot from the installed package, including its checksum, standalone restore
and full committed-table/schema equality. Preserve all manual baseline hashes.
The trigger is writable startup or the next outer write after due time, not a
wall-clock scheduler. Record actual destination/configuration only in private
installation evidence; public records contain sanitized results and hashes.

Candidate, publication, fresh installation, production preservation and activation
are distinct evidence gates. Unexecuted gates stay PENDING or INCONCLUSIVE;
source/candidate PASS cannot imply publication or activation PASS. Store failures,
partial publication, initial installer attempts and harness corrections are
retained. Final COMPLETE requires every applicable gate; otherwise report
BLOCKED or EXHAUSTED with the concrete unmet condition. At most two repair rounds
and at least 25% verification reserve. No original frozen artifacts may change.
