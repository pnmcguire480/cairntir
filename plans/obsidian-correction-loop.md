# Explicit Obsidian correction loop

Single existing foundational feature, based on reviewed PR125. Source 1.15.0 is
unpublished. The preserved Week 1 correction plan supplies the contract: explicit
workspace refresh, append-only correction, durable acknowledgements and safe
retries. The workspace is a prerequisite for the separately planned question
and resolution loop; that next feature is not included here.

## Acceptance

- Bind each explicit request to its UUID, wing, source local/portable identities
  and exact UTF-8 content hash. Preserve original content, provenance, retrieval
  layer, privacy and lifetime; append an untrusted correction and supersedes edge.
- Reject malformed, stale, hidden, secret and structured workflow edits. Exact
  retries survive restart without duplicates; changed payloads conflict.
- Consume only retained outbox JSON requests. Separate database commitment from
  acknowledgement/projection failures; partial success is never silent success.
- Project current/history links and exact manifest text. Preserve human bytes
  outside owned Markdown markers and confine all file operations to the vault.
- Optional desktop plugin uses explicit configured executable/home/wing,
  shell-free bounded child execution, source recheck, explicit submission and
  matching receipt validation. Load/cancel/ordinary edits do not submit writes.
- Preserve legacy Obsidian commands, existing grants, source/coverage gates,
  schema, dependencies and 21 MCP tools. No real vault/store/install changes.

Independent public frozen tests and fresh base/candidate controls precede
qualification. Reserve at least 25% for verification with at most two product
repair rounds. Normal required exact-head hosted CI and parent independent review
must pass before the next sequential feature. Native graphical Obsidian use and
actual user adoption are unverified by mock/process tests and must not be claimed.
The wider parked program is preserved, not reintroduced as this feature's gate.

See [the operator guide](../docs/obsidian-corrections.md). No merge, publication or
installation occurs within this feature checkpoint.
