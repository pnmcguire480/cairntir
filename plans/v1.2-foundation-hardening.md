# v1.2 — Foundation Hardening

**Status:** implemented in the working tree; release-candidate verification active
**Accepted:** 2026-07-27
**Source:** deep modernization audit, Cairntir drawers #110 and #111

## Why this phase exists

Cairntir is now being used as the memory substrate for an external agent
system. That changes the reliability bar. Before adding reach, sync, or more
agent behavior, the existing memory substrate must prove that it cannot
silently mix incompatible embeddings, lose scoped results, hide verbatim
content, or leave workflows half-committed.

This is not a rewrite. The three-skill core, local-first ownership, SQLite
default, verbatim floor, prediction-bound drawers, append-only evidence, and
recipe model remain locked.

This phase is also the trust substrate for the Evolving Mind North Star in
`plans/evolving-mind.md`. Recursive learning cannot safely compound over mixed
embeddings, truncated evidence, divergent host stores, incomplete provenance,
or half-committed workflows.

## Workstreams

### 0. Lineage recovery

- Treat BabyTIEROS → BrainStormer → Cairntir as the direct evolutionary line.
- Maintain the feature survival map in
  `docs/lineage/evolution-audit-2026-07-27.md`.
- Every new mechanism states which ancestral user outcome it preserves,
  replaces, or deliberately rejects.
- Restore outcomes, not old subsystems: core invariants for correctness,
  recipes for protocols, projections for human interfaces, and host
  responsibilities for orchestration.

### 1. Semantic-index integrity — ship blocker

- One production embedding-provider factory for CLI, MCP, daemon, setup,
  recipes, and evaluation.
- Persist the embedding provider/model identity, vector dimension, index
  generation, and verification time.
- Refuse semantic reads and writes when the stored embedding space is unknown
  or does not match the active provider.
- Keep raw drawers readable during a mismatch.
- Add `cairntir doctor` and an explicit, backed-up `cairntir reindex`.
- Refuse databases whose schema version is newer than the running library.
- Regression tests must reproduce cross-provider contamination and prove it is
  rejected.

### 1A. Multi-host continuity — ship blocker

- Codex, Cursor, and Claude Code connect to the same canonical local database
  and MCP server; no host-specific memory stores or embedding providers.
- Keep the memory core host-neutral. Put registration and startup-instruction
  behavior behind thin host adapters.
- Install the same session-start / remember / recall contract into `AGENTS.md`,
  Cursor project rules, and `CLAUDE.md` without maintaining three divergent
  copies of the policy text.
- Resolve the wing from the same canonical project identity across hosts.
- Record host, agent/model identity when available, client version, session ID,
  and tool-surface version as provenance—not as retrieval semantics.
- `cairntir doctor` reports registration and reachability separately for
  Codex, Cursor, and Claude Code, plus whether all three resolve the same
  database and embedding generation.
- Add adapter contract tests and a three-host continuity acceptance test:
  remember in host A, recall verbatim in hosts B and C.
- Follow each host's current official configuration surface; isolate those
  changing details so host churn cannot leak into the memory core.

### 2. Correct scoped retrieval

- Apply wing, room, layer, validity, and trust filters inside the sqlite-vec
  nearest-neighbor query.
- Add a crowded-index regression where the only in-scope result is outside the
  global top-K.

### 3. Exact retrieval contract

- Expose complete drawers through MCP resources or a structured `get` surface.
- Search results carry a snippet, content length, content hash, truncation
  marker, and stable resource reference.

### 4. Durable workflows

- Stable run IDs, idempotency keys, explicit workflow states, and recovery for
  Reason, recipes, and daemon capture.
- WAL, busy timeout, integrity checks, and backup-before-migration.

### 5. Trust and provenance

- Source, trust, visibility, sensitivity, and validity metadata.
- Imported and captured content is untrusted by default.
- Prompt-safe memory rendering and persistent-injection regression tests.

### 6. Release integrity

- Reconcile local, GitHub, tag, PyPI, documentation, and memory version claims.
- Package recipes in wheels.
- Move legacy sentence-transformers/Torch support to an optional extra.
- Replace the regex silent-exception scanner with an AST check.
- Trusted Publishing, attestations, and pinned CI actions.

### 7. Earned post-foundation recipe: CodeGlass

- Preserve CodeGlass's actual user outcome: teach Patrick and other vibecoders
  with minimal or no formal CS training how unfamiliar code works.
- Treat the high-quality Anthropicer walkthroughs as evidence for the intended
  output, not as evidence that BrainStormer's generator produced them.
- Replace the shallow regex/diff generator with a cited, evidence-aware,
  uncertainty-labeled teaching recipe plus teach-back.
- Project verified walkthroughs into Anthropicer while keeping SQLite as the
  authoritative store.
- Implementation contract: `plans/codeglass-recovery.md`.
- Sequence after semantic integrity, exact retrieval, provenance, and durable
  workflow foundations are reliable.

## Ship gates

- No unverified or mismatched embedding space can service semantic reads or
  writes.
- Reindex is atomic from the caller's perspective and creates a backup first.
- CLI, MCP, and daemon use the same production provider identity.
- Codex, Cursor, and Claude Code resolve the same store path, embedding space,
  and index generation.
- Full tests, Ruff check + format, mypy strict, build, wheel-content inspection,
  and the silent-exception scanner pass.
- The live store is reindexed only through an explicit operator action.

## Implementation snapshot — 2026-07-27

The working tree now implements workstreams 0–5 and the CodeGlass recovery
substrate:

- schema v6 carries immutable write provenance, trust, visibility,
  sensitivity, validity, and durable workflow receipts;
- nested transactions/savepoints plus `execute_once` make Reason, recipes,
  replay, imports, daemon capture, and CodeGlass retry-safe;
- retrieved memory is rendered as untrusted evidence with explicit
  instruction-authority and injection-signal fields;
- automated adapter tests prove Codex, Cursor, and Claude Code share one store
  while retaining host/model/session provenance;
- repeated Reason episodes can propose—but never auto-promote—calibrated
  Discovery Ledger candidates;
- calibration, CodeGlass teach-back/retention, and one-way
  Anthropicer/Obsidian projection are available.

Remaining release-candidate work is deliberately operational: run the
human-operated three-host smoke test, exercise migration/reindex against a
copy of the live database, and then reconcile version/tag/PyPI/release notes.
