# E23 public recall response-budget acceptance

Independent public acceptance, frozen before implementation. Shared workspace; no private evaluator claim. Tests use temporary stores and fixed HashEmbeddingProvider fixtures; real stdio MCP transport is required. No production store/configuration changes or model downloads.

1. `cairntir_recall` publishes optional `budget_chars`, strict integer 1024 through 262144 inclusive. Booleans, nonintegers, null and out-of-range values are rejected. The bounded backend seam is `CairntirBackend.recall_bounded(*, query, wing=None, room=None, limit=10, full_content=0, budget_chars)` returning a JSON string; invalid budget raises typed MCPError. Omitted MCP budget continues through unchanged legacy recall behavior.
2. Accepted budget measures the complete `types.CallToolResult.model_dump_json()` string length, excluding outer JSON-RPC framing. Headers, evidence, routing/omission metadata, escaping and envelope overhead all count. A raw content-length limit is insufficient. The actual server must not append update notifications outside the budget. Bounded reports explicitly set `notification_policy: "excluded"`.
3. Bounded text schema is `cairntir.recall-budget.v1`, with `status` complete/partial/omitted, `instruction_authority: "none"`, `budget: {limit_chars}`, `evidence: [...]`, `omitted: {count, drawer_ids, ids_complete}`, and `notification_policy: "excluded"`. Complete means zero omitted hits; partial means complete evidence plus omissions; omitted means matched hits but no included evidence. Empty search is complete with empty lists. Additional truthful fields are allowed.
4. Each included evidence entry contains exact drawer_id, content, content_sha256 (UTF-8), and complete exact provenance. Content is never truncated or normalized; hashes are derived from original text. Only whole entries fit. Omitted IDs are valid retrievable source IDs, disjoint from included IDs; omitted count accounts for every withheld hit. If the ID list itself cannot fit, truncate that list explicitly with ids_complete false and retain the total count. Evidence retained under the budget remains usable evidence, never a snippet presented as complete.
5. Preserve full_content selection semantics: only the top N hits are eligible for complete evidence; a too-large requested hit may be omitted while a later requested hit fits. `full_content=0` provides bounded routing omission receipts and no evidence snippets. Adversarial coverage includes many hits, oversized leading evidence, escaped/Unicode text, large provenance, huge no-hit query, boundary budgets, and a pending update banner. Do not echo unbounded query text.
6. Verify schema and enforcement through actual MCP stdio, not only direct Python calls. A temporary server built with the real `build_server` and backend plus HashEmbeddingProvider is acceptable transport evidence; final installed production-launcher/cache proof remains separately labelled. Wrong controls must demonstrate that measuring raw content instead of the serialized envelope, or appending a banner after budgeting, fails acceptance. Preserve fixtures and failed results; one implementation round plus at most two repairs and at least 25 percent verification effort.

These are behavior requirements, not permission to begin implementation. Executable tests will be frozen in a separate manifest before their first run.
