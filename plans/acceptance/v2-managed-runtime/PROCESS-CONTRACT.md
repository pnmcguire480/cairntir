# Managed actual-process supplement v1

Frozen independently after core protocol, before candidate dispatch implementation. CONTRACT.md and CORE-FROZEN.json remain unchanged. This supplement's drivers use actual SQLite stores, candidate ManagedRuntime and real Python subprocesses. HashEmbeddingProvider is used only in the class-level synthetic store fixtures. The actual CLI case uses a caller-supplied qualified production model cache copied into its disposable directory, with offline flags; absence is a failed prerequisite, not a skipped passing gate.

`process_child.py` opens a separate read-only SQLite connection and requires exactly one committed managed.dispatch.v1 receipt for its action ID, plus the exact claim/predicted_outcome row. Only then does it append and fsync an external marker. The marker is the independent observable effect; the candidate's own success flag cannot substitute for it.

`process_driver.py` injects faults only at witnessed boundaries: selected profile Popen pauses before actual spawn; managed.outcome.v1 persistence raises a known storage exception after the child effect. Unwitnessed injection fails the test. Parent kills only its own driver handles; controlled children are released to finish, and do not run indefinitely. Recovery uses a fresh process and unchanged original action request. There is no live database or project action.

The caller's outer transaction is a load-bearing boundary. If dispatch is invoked inside an already-open owner or ScopedStore transaction, it must reject before Popen and before any durable launch permit. Merely exiting a nested savepoint cannot establish pre-action durability. A tiny authorized read-only `transaction_active` store property is an acceptable implementation seam; raw ScopedStore owner access is not. The same authorized action must succeed outside the caller transaction as a positive control.

Two drivers independently obtain valid current acknowledgements, rendezvous before dispatch, and race the same action ID. Their acknowledgement IDs differ, so one is a legitimate competing payload and must fail; exactly one child marker and one committed intent are allowed. This proves the observable at-most-one action-ID rule without forging a shared runtime epoch.

The explicit wrong control uses a separate writer transaction containing an uncommitted prediction/intent and runs the real child. The child must refuse before its external marker. A passing committed control must produce the marker. This independently qualifies the pre-action oracle before candidate execution. In addition, candidate mutation review must exercise outcome-less-intent replay; a second marker falsifies the at-most-one requirement. The latter mutation is applied only to a disposable candidate copy after one exists, never by changing assertions.

Run: set PYTHONPATH to the reviewed source or use its reviewed installed interpreter, set PYTHONUTF8=1, set MANAGED_ACCEPTANCE_MODEL_CACHE to the qualified public cache, and run test_managed_process.py. A result is scoped to managed sessions, not native coding-host event delivery, OS isolation, arbitrary descendant containment or R10 generated Last Session. Product and acceptance hashes must be recorded before and after execution.
