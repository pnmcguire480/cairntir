# Required managed event visibility

One additive check exercises the existing complete-evidence and truthful capture
contracts. A fully authorized runtime commits two exact events and closes with
watermark two; owner projection positively establishes complete history. A separate
drawer-limited grant sees the first event but hides the second required checkpoint
and source. Its selected task/brief cannot become complete. Close may refuse with
the existing typed error or explicitly report incomplete capture; it cannot certify
the visible subset as the complete session. No hidden text or portable identity is
disclosed. Projection refuses without publishing a success snapshot or changing the
prior view or database. Full owner access still reproduces the complete prior view.

This follows the historical managed CONTRACT: whole required evidence must be
visible; inaccessible task evidence makes briefs incomplete; close cannot claim
all captures delivered merely by matching a visible watermark. It does not import
R18's metrics semantics, create a new policy, require inaccessible-ID disclosure,
or broaden native host delivery. The complete v1 24-case freeze remains unchanged.
This new check freezes independently before execution. No runtime fix is assumed.
