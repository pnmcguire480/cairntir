# Week 1 public correction core acceptance

Independently authored and frozen before implementation. Shared-workspace public tests; no private custody or hidden evaluation claim. Isolated temporary real SQLite stores and HashEmbeddingProvider only.

Interface: cairntir.obsidian_bridge.apply_correction(store, request:dict, *, wing:str)->dict and typed CorrectionError. Request schema cairntir.obsidian-correction.v1 has request_id UUID, wing, positive non-bool source_drawer_id, source_identity UUID from portable_identity, lowercase source_sha256 of exact UTF-8 content, and exact nonblank content. Receipt schema cairntir.obsidian-correction-receipt.v1 has status committed, request_id, source_drawer_id, source_identity, correction_drawer_id, content_sha256 and boolean replayed.

Acceptance: append exact content without modifying original drawer/provenance/identity; preserve room/layer and explicit supersedes relation. Durable replay survives reopening and returns original receipt even though original source is now historical. Changed payload under same request ID conflicts; fresh request on historical source conflicts; current correction can receive a further correction. Validate source hash, local ID, portable identity and fixed/request/source wing, including cross-store ID/hash collision. Correction trust is UNTRUSTED and inherits source sensitivity/visibility; SECRET and structured machine lifecycle sources (at least task_checkpoint, CodeGlass and discovery) are refused. Malformed requests never append. Failure after append rolls back the durable operation and allows a successful retry. Existing handoff with sufficient budget returns the exact ordinary on-demand correction after reopening. DEEP remains DEEP, to be reflected through later explicit workspace inventory.

The original source ID acts as optimistic version: new edits must target the current unsuperseded drawer. No separate revision counter is required. Committed means persisted evidence, not authenticated human authorship or factual endorsement.

Twelve executable tests include malformed-field subcases and injected post-append failure. No production store, model execution, installation or service required. File workflow/plugin acceptance will be frozen separately before that implementation. One implementation round and at most two repair rounds; reserve at least 25 percent of effort for verification. Existing frozen artifacts remain unchanged.
